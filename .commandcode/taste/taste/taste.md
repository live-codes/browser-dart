# Taste
- Prefers to start with a minimal, standalone proof-of-concept (e.g. a single simple HTML page) to validate feasibility before doing a full integration into a larger codebase. Confidence: 0.65
- Expects third-party dependencies that are pinned/vendored to be revisited when upstream releases land, and wants an explicit assessment of what each upgrade changes for the project's work — not just a version bump. Confidence: 0.5
- Wants new npm packages to follow the established `@live-codes/*-wasm` family conventions — naming and structure mirroring existing siblings (e.g. `@live-codes/clang-wasm`, `@live-codes/swift-wasm`) rather than inventing a new shape. Confidence: 0.75
- Prefers build artifacts to be committed to the repository, including large vendored SDK/asset trees, rather than gitignored. Confidence: 0.6
- Prefers client-side / serverless solutions — features should run entirely in the browser with no backend or server-side compilation ("no servers"). Confidence: 0.6
- Treats access to generated/compiled output and source maps as first-class requirements: wants the emitted code (e.g. the compiled JS) exposed and wants source-mapped stack traces, not opaque blob URLs. Confidence: 0.5
- Pushes back on architectural constraints stated without evidence ("why does it need X? can't we do Y instead?"), and expects claims to be verified against the actual source/behavior before they are used to justify a design. Confidence: 0.5
- Prefers APIs split by responsibility over a single convenience call: when compiling and running can happen in different contexts (compile off the main thread, run wherever the output belongs), wants explicit, composable primitives (e.g. a separate `compile` and `run`/runner) rather than one bundled entry point — a monolithic wrapper should just be the primitives wired together. Confidence: 0.55
- Expects the agent to work from the repository's own documentation: points to the relevant contribution/guide file (e.g. `docs/.../adding-languages.mdx`) instead of restating the requirements, and expects conformance to the project's documented conventions and existing sibling implementations rather than an invented shape. Confidence: 0.5
- When a task spans sessions or gets cut off mid-way, wants a written handover artifact (a markdown file in the working repo) capturing findings, current state, blockers, and next steps so a fresh session can resume — rather than relying on conversation history. Expects it ordered by what a fresh session needs first (blocker and its evidence up front, then the verified work, then the remaining checklist, environment gotchas, and an explicit verification order), with retracted/wrong claims flagged as "do not act on" and verified findings kept clearly separate from speculation. Confidence: 0.6
- Cares about published packages staying servable from public CDNs and their size limits (e.g. jsDelivr's 150 MB unpacked cap), and is willing to accept runtime cost/complexity — shipping assets compressed and inflating them before use — rather than dropping features or assets to fit. Confidence: 0.55
- During development, prefers to keep everything pointed at local assets/dev servers ("stay on local for now") rather than flipping configuration to published/CDN versions — localhost bases and uncommitted local wiring are fine until the user says otherwise. Confidence: 0.5
- Wants changes committed locally but explicitly NOT pushed or published — keeps push/publish under their own control and expects the agent to stop at a local commit unless told otherwise. Confidence: 0.6
- After a destructive operation rewrites history (or otherwise changes shared state), wants the rollback safety net retained — keeps the backup branch/bundle in place rather than letting the agent clean it up and prune/`gc` immediately, even if that leaves large old objects in the local repo. Confidence: 0.5
- Reports failures by pasting raw output verbatim — browser console logs, network errors, git push rejections, and stack traces — without paraphrasing or adding prose, and expects the agent to diagnose from the raw text. Confidence: 0.65
- Wants the user-facing console/pad output to contain only what the user's program actually prints — internal SDK/toolchain chatter (e.g. `dartDevEmbedder.runMain`'s "Starting application from main method in: …") should be suppressed rather than shown, matching how the project's other languages behave. Confidence: 0.5
- Wants user-facing additions (e.g. a new language's starter template) to match the shape of the existing siblings — the same pattern and content as the other languages ("Hello, {lang}!", logo, counter) rather than an invented look — and states this expectation explicitly ("similar to other languages"). Confidence: 0.6
- Treats failing/spurious network requests (browser-console 404s and `net::ERR_ABORTED` on asset fetches) as bugs to fix, not benign noise to tolerate — expects the code to request only assets that actually exist (e.g. probe `${url}.gz` only for known-compressed assets) rather than guess-and-404. Confidence: 0.55
